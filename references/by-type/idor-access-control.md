## 适用信号与前提

资源 ID、租户字段、管理接口、列表/详情/导出/批量接口、可写对象属性。先按 [业务建模](../business-modeling.md) 确认资源归属和共享规则，准备独立的 A/B 测试会话；垂直测试须有真实角色依据。

## 最小实验

1. 按 [业务预期判定](../business-intent.md) 确认本次操作/字段的允许受众与授权方式，再准备带唯一标记的受控资源。私有对象使用 A/B 独立会话；匿名边界使用干净访客与所有者对照；公开对象先验证其真实可见性，不默认改成私有资源。核对实际身份及令牌来源。
2. 在同一已知资源/动作上只更换测试身份，或固定身份只更换为另一个测试资源 ID；不要同时改变多个条件。
3. 保存应用结果与真实数据/状态。详情、导出、批量、不同方法和可写字段是不同权限入口，按已观察功能选择。

## 确认与反例

确认需要证明本来无权的身份读到另一账号下的唯一内容（自建受控资源，或按下文动作边界允许读取的他人账号对象），或实际完成被禁止的动作/字段变更。HTTP 200、存在响应、UI 显示成功都不充分。

排除公开资源、分享链接、角色委派、同租户合法共享、后台继承权限、缓存和会话串用。签名 URL 可访问是否为漏洞取决于签发、使用和时效规则，不能仅因无需 Cookie 就认定未授权。

## 下一步、停止与报告

有证据时保存最小发现；无法确认归属则待补证。没有第二角色/第二账号时不停止该分支：按下文「单账号判定」用自有基线 + 归属字段 + 公开佐证推进，只把「必须双账号才能出的证据形态」记待补证。读取与写入分开定界：**查**可对他人账号进行（用 A/B 独立会话读对方真实对象，证明跨账号可见），但以已知对象标识优先（已知标识不足时按下文「单账号判定」做小批量抽样），只取证明所需的最小对象与字段，不做全量遍历、不批量导出、不留存不对外传播他人数据；**增、删、改**只针对自己控制的账号与内容，并记录恢复结果。项目条款更严时（只在自己创建的账号间互测、禁止接触线上用户账号、限定可读组数）以项目条款为准，见 [项目规则库索引](../policies/index.md)。

报告附角色/租户别名、资源归属、对照请求、实际结果及共享规则证据。统一遵守 [验证标准](../verification.md)。

## 单账号判定：大范围、小批量枚举

缺第二账号不是停测条件：越权要回答的是「这个对象是否本不该被我看到」，单账号就能答，只是证据形态要写清。

1. **建自有基线**：用自有账号取详情、导出、附件各一条自有对象，记下自有 `id/uid/orgId`、响应里的归属字段（昵称、所属组织、创建时间、金额尾数）与请求形态，作为对照组。
2. **定枚举空间**：优先用**已知存在**的他人对象标识——分享页、公开主页、搜索索引、列表里的他人条目、正常流量里的 `id/uid/corp_id/file_id`；确实没有已知标识时，才在已获准的动作上做有界抽样（数字 ID 取相邻区间、UUID 取同前缀样本），每批 3–5 个，不在同一路径连续试探。
3. **大范围铺开、小批量试探**：每批只改对象标识一个变量，横向铺到不同 ID 空间与不同业务入口（详情、列表、导出、附件、历史版本、异步结果下载），而不是在同一入口把 ID 加到几百个。
4. **归属三要素**（缺哪条就把哪条记为待补证）：①标识不等于自有标识；②响应内容属于他人且归属字段可独立核对；③公开侧能独立佐证该对象属于他人（公开主页、搜索索引、分享页、时间一致）。
5. **命中即停**：出现非自有对象可见就停止扩大，转最小复现——自有基线、他人对象请求响应、公开佐证各一段，不追加样本、不导出、不留存。
6. **证据强度分层**：单账号 + 公开佐证 = 可提交候选（报告写明证据形态）；双账号同请求对照 = 最强形态；平台明确要求双账号（见 [项目规则库索引](../policies/index.md)）时按项目条款，另记待补证，仍不因此停测。
7. 本节只覆盖**查**；增、删、改仍只针对自己控制的账号与内容。

语料里「单账号只能证明接口返回了东西」指的是**缺少归属佐证**的情形，不是禁止单账号判定；补上第 4 步即能区分「返回了东西」与「返回了别人的东西」。全量遍历、顺序爆破式扫号、爬取建库仍然禁止。

## 调研补充：可执行检查点

| 检查点 | 最小对照与判定 |
|---|---|
| 同一对象的不同入口 | 从正常流量找详情、附件、导出、历史版本等实际入口；对 A/B 自建私有对象各选一对，避免只覆盖列表接口。 |
| 对象与父级归属 | 比较 URL 父对象、body 对象、租户上下文的一致性；对象本身与所属项目都要验证，不能假设 UUID 就是授权。 |
| 功能与方法 | 仅对已观察且获准的方法检查低角色能否触发相同管理操作；菜单隐藏、OPTIONS 或 405 都不能证明实际授权。 |
| 批量与异步 | 用两个已知自建对象检查是否逐对象授权；任务创建、结果下载、分享撤销分别是检查点。 |

Agent 输出角色×对象×动作×状态矩阵；工具管理独立会话并保存服务端结果。响应里出现字段但归属不明，先补对象来源，不随机枚举 ID。字段级问题转 [API 属性授权](api-property-pollution.md)。

## 归档案例补充：关联入口和子对象

详情拒绝不代替列表、导出及下载的授权检查；父任务有权限也不代替引用子任务的权限。候选来自正常流量或获准源码，使用受控对象观察后台实际效果。共享令牌查无记录时检查失败分支，排除合法分享。见 [K03、K06–K07](../research/crawl-xz-patterns.md)。

## 同类项目成交语料补充（匿名归档，未复现）

来源：[corpus-web-logic-authz.md](../research/corpus-web-logic-authz.md)（真实提交→审结记录，未经复现；来源已匿名，归档无忽略原因字段，勿当规则）。

- 管理后台"全租户"动作（删除/编辑某类全部资源）比单对象越权更容易成片命中，检查点是把 `orgId/tenantId` 纳入 SQL 条件而非只判"已登录/是管理员"。
- 数组参数（`file_ids`/`userids`/`addStaffs`）常只校验首元素：用一个自有 + 一个他人的混合数组验证逐元素授权。
- 未认证签发对象存储上传/读取凭证（签名服务不校验调用方、`key`/`md5` 由客户端决定、前端泄漏 CDN 密钥）是独立高发类。
- 组织维度固定值（`compid`/`orgId`/`group_id`/全站同一 token）取到即等价全站权限，价值高于遍历自增 id。
- 证据优先用"双账号同请求仅差一个 id/scope + 受害者终态回查"；三自建账号互测最不易被质疑。
